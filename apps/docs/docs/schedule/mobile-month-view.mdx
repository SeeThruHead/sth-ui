## Usage

`schedule.MobileMonthView(h, { date, events, selectedDate })` shows the month containing `date` as a compact calendar
whose days carry up to three event dots, with the events of `selectedDate` (today when left out) listed underneath,
including multi-day and recurring events. The selection is yours: `onDayClick` reports the day tapped, so keep it in
your model and pass it back. `onEventClick`, `onWeekNumberClick` and `onYearClick` (the back button with the year)
report the other taps, and arrow keys move between days.

## Options

`withWeekNumbers`, `withWeekDays`, `weekdayFormat` (`dd`), `firstDayOfWeek`, `weekendDays`, `withWeekendDays`,
`withOutsideDays`, `consistentWeeks` and `highlightToday` work as in the [MonthView](/schedule/month-view).
`eventsHeaderFormat` (`dddd, MMMM D`) titles the list, `renderHeader` replaces the header (it receives the default
one), `renderEvent` replaces each listed event, and `getDayProps` and `getWeekNumberProps` add attributes.

## Differences from Mantine

- The selected day is controlled only: there is no `defaultSelectedDate`, and `onDayClick` stands in for
  `onSelectedDateChange`.
- `now` is a prop rather than read from the clock.
- `renderHeader` receives the default header as nodes, and `renderEvent`, `getDayProps` and `getWeekNumberProps` work
  with attribute lists instead of React props.
