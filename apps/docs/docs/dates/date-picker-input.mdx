## Usage

DatePickerInput is a button-like input that opens a [DatePicker](/dates/date-picker) in a Popover. Keep
`PickerInput.init({ id, today, level: "day", type, value })` in the Model, route its Messages through
`PickerInput.update(model, message, options)` and its Commands back to the runtime, and render it with `model` and
`toParentMessage`. `update` reports `Changed` with the new value, and `Opened` and `Closed`. The value is shown as
`MMMM D, YYYY` by default; label, description, error, sections and the other Input props work as on TextInput.

## Types, presets and formats

- `type: "multiple"` keeps the dropdown open and sorts the dates (`sortDates`, an `update` option, turns that off).
- `type: "range"` closes once both ends are picked; closing with only a start drops it, as Mantine does.
- `closeOnChange: false` (an `update` option) keeps the dropdown open after a pick.
- `valueFormat` (dayjs tokens, `"MMMM D, YYYY"` by default), `labelSeparator` and `valueFormatter` shape the text, and
  `clearable` adds a clear button once there is a value.
- `presets`, `numberOfColumns` and every other DatePicker prop go to the dropdown; `popoverProps` to the Popover.
- `name` writes the value into a hidden input for forms, in Mantine's format.
- `readOnly` and `disabled` keep the dropdown shut.

## Differences from Mantine

- It is a submodel (`init`, `update`, out messages) rather than a controlled or uncontrolled component.
- `dropdownType="modal"` is not supported; the dropdown is always a Popover.
