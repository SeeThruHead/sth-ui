## Usage

`PasswordInput` is a [TextInput](/inputs/text-input) for passwords: every Input and wrapper prop, a
`type="password"` field and a button that shows or hides what was typed. The button is shown when you pass
`onVisibilityChange`; keep `visible` in your model and flip it from that message.

<Configurator story="inputs-passwordinput--configurator" />

## Loading state

`loading` shows a loader in the right section, in place of the toggle.

<Example story="inputs-passwordinput--loading" caption="Loading" />

## Controlled

Keep the value in your model and update it from `onInput` (each keystroke) or `onChange` (on commit), as with
[TextInput](/inputs/text-input).

## Uncontrolled

Without `value`, the field keeps its own text; give it a `name` and it is sent with its form.

## Controlled visibility toggle

`visible` and `onVisibilityChange` are Mantine's controlled visibility: two fields that read the same `visible`
reveal and hide together.

## Change visibility toggle icon

`visibilityToggleIcon` is a function of the builder, whether the text is shown, and the icon size for the input's
size (20px at `sm`).

## Accessibility

The toggle is a button named "Toggle password visibility" with `aria-pressed` saying whether the text is shown. It is
left out of the tab order by default, so Tab goes from the field to the next field; `visibilityToggleFocusable`
puts it back, after the field.

<Example height={300} story="inputs-passwordinput--focusable" caption="The toggle in the tab order" />

## Differences from Mantine

- The visibility is always yours to keep (`visible` and `onVisibilityChange`), since a Foldkit view holds no state;
  there is no `defaultVisible`.
- The field is the Input's own `input` (part `input`) rather than an inner input inside a `div` (`innerInput`).
- The toggle keeps the default radius instead of following `radius`, and the default icon is Phosphor's eye.
