## Usage

SegmentedControl is built on `@foldkit/ui`'s radio group: keep `SegmentedControl.Model` (from
`SegmentedControl.init({ id })`) and the chosen `value` in your model, pass its messages through
`SegmentedControl.update`, and take the new value from its `Selected` out message. Without a `value` the first item
is chosen. Name the group with `ariaLabel`.

<Configurator story="inputs-segmentedcontrol--configurator" />

## Controlled

SegmentedControl is always controlled: `value` is what it shows.

## Data prop

`data` takes strings, or items with a `value`, a `label` (any content) and `disabled`.

## Transitions

The indicator slides to the chosen segment over `transitionDuration` (200ms by default) with
`transitionTimingFunction`. It is placed with CSS anchor positioning, so nothing is measured in JavaScript.

## Accessibility and usability

The control is a `role="radiogroup"` and each segment a `role="radio"`; only the chosen segment is in the tab order,
and the arrow keys of its `orientation` move to the next segment and choose it. Name the group with `ariaLabel`, and
for icon-only segments put a visually hidden label next to each icon.

<Example story="inputs-segmentedcontrol--icons-only" caption="Icons with visually hidden labels" />

## Differences from Mantine

- State lives in your model; there is no `defaultValue`.
- The indicator follows the chosen segment with CSS anchor positioning instead of
  measuring the segments; where anchor positioning is missing it does not show.
- The arrow keys follow `orientation` instead of both directions.
