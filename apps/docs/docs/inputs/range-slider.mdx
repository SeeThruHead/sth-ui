## Usage

RangeSlider picks a range with two thumbs. Keep `RangeSlider.Model` (from `RangeSlider.init({ id, min, max, step })`)
and the value `[from, to]` in your model. Pass its messages to `RangeSlider.update` with
`RangeSlider.rangeContext({ ...rules, value })`, and take the new range from its `Changed` out message (and
`ChangeEnded` when a drag or key press ends). Lift `RangeSlider.subscriptions` so dragging follows the pointer.

It takes Slider's `size`, `radius`, `color`, `thumbSize`, `marks`, `label`, `labelAlwaysOn` and `showLabelOnHover`.

By default a thumb that reaches the gap pushes the other one along. With `pushOnOverlap={false}` it stops instead.

`inverted` fills the track outside the range instead of inside it.

## Accessibility

Each thumb is a `slider` with `aria-valuemin`, `aria-valuemax` and `aria-valuenow`. Name them with
`thumbFromLabel` and `thumbToLabel` (or `thumbLabel` for both), and give `thumbValueText` for a spoken value. With a
`name`, two hidden inputs `<name>_from` and `<name>_to` carry the value in a form.

## Keyboard interactions

| Key                   | Description                                                       |
| --------------------- | ----------------------------------------------------------------- |
| ArrowRight / ArrowUp  | Increases the focused thumb by one step (or to the next mark)     |
| ArrowLeft / ArrowDown | Decreases the focused thumb by one step (or to the previous mark) |

## Differences from Mantine

- RangeSlider is always controlled; there is no `defaultValue`.
- `labelTransitionProps` is not ported: labels fade in and out.
- `thumbChildren` takes one child for both thumbs or a pair, one for each.
