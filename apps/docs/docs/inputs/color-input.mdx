## Usage

ColorInput is a text input with a colour preview on the left, an eye dropper on the right and a ColorPicker in a
dropdown that opens when the input is focused or clicked. Keep `ColorInput.Model` (from
`ColorInput.init({ id, value })`) and the value string in your model, pass its messages through
`ColorInput.update(model, message, ColorInput.colorInputContext(props))` and lift `ColorInput.subscriptions` so
dragging in the picker follows the pointer. It takes every Input and Input.Wrapper prop: label, description, error,
sizes, radius, variants, sections and loading.

<Configurator story="inputs-colorinput--configurator" />

## Controlled

The `Changed` out message carries the value as it is typed or picked; `ColorInput.setValue(model, value)` sets it
from outside.

## Formats

`format` is `hex` (the default), `hexa`, `rgb`, `rgba`, `hsl` or `hsla`. Values picked in the dropdown or with the
eye dropper come out in that format, and the alpha slider is shown only for `hexa`, `rgba` and `hsla`:

## fullWidth

`fullWidth` makes the dropdown as wide as the input and stretches the picker inside it.

## Styles API

Its parts are Input and Input.Wrapper's (`root`, `label`, `required`, `description`, `error`, `success`,
`wrapper`, `input`, `section`, `bottomSection`), `dropdown`, `colorPreview`, `eyeDropperButton`,
`eyeDropperIcon`, and ColorPicker's parts for the picker in the dropdown. The dropdown carries
`data-color-input-dropdown` and the preview `data-color-preview`.

## Accessibility

The input is a labelled textbox; the picker in the dropdown is kept out of the tab order, so keyboard users type
the value. The eye dropper button is named "Pick a colour from the screen".

## Differences from Mantine

- State lives in your model, and dragging in the picker needs the subscriptions lifted into yours.
- There is no `popoverProps`; `withinPortal` (on by default) chooses whether the dropdown moves to the body.
- The dropdown fades in and is placed bottom-start, 5px below the input, like Mantine's.
