## Usage

Table's `children` is a function of a builder `t`, with Mantine's parts as functions: `t.caption`, `t.thead`,
`t.tbody`, `t.tfoot`, `t.tr` (with `bg` and `attributes`), and `t.th` / `t.td` (with `w`, `colSpan`, `rowSpan` and
`attributes`). Rows and cells learn their place from the section they are in, so stripes, row borders and column
borders follow it as Mantine's selectors do.

```ts
ui.Table(h, {
  children: (t) => [
    t.thead([t.tr(headings.map((heading) => t.th([heading])))]),
    t.tbody(elements.map((element) => t.tr([t.td([element.name]), t.td([element.symbol])])))
  ]
})
```

## Sticky header

`stickyHeader` keeps the head in view while the table scrolls; `stickyHeaderOffset` moves it down, for example below a
fixed header.

## Spacing, borders, stripes and hover

`horizontalSpacing` (`xs`) and `verticalSpacing` (7px) pad the cells. `withRowBorders` (on), `withColumnBorders` and
`withTableBorder` draw lines in `borderColor`. `striped` (`true` or `"odd"`, or `"even"`) shades rows with
`stripedColor`, and `highlightOnHover` shades the row under the pointer with `highlightOnHoverColor`.

## Scroll container

`ui.TableScrollContainer` gives the table a `minWidth` and an optional `maxHeight`, scrolling the rest. With a
`scrollArea` (a [ScrollArea](/miscellaneous/scroll-area) model and its messages) it scrolls in a ScrollArea; without
one it uses the browser's overflow.

## Styles API

Its parts are `table`, `thead`, `tbody`, `tfoot`, `tr`, `th`, `td` and `caption`; the scroll container's are
`scrollContainer` and `scrollContainerInner`. Rows carry `data-with-row-border`, `data-striped` and `data-hover`, cells
`data-with-column-border`, the head `data-sticky` and the caption `data-side`.

## Differences from Mantine

- The compound parts (`Table.Thead`, `Table.Tr` and the rest) are the builder's functions.
- TableScrollContainer scrolls natively unless given a ScrollArea model.
